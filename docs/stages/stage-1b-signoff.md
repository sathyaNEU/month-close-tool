# Stage 1b sign-off

Stage 1b was signed off on 2026-09-27. The gate result is in [stage-1b-report.md](stage-1b-report.md) (PASS, 27 of 27 criteria, with the Stage 0 and Stage 1a checks re-run as regression), measured with the Docker VM at 11.67 GiB.

The sign-off accepted the deviations listed in the report's summary, which are the `spark-connect` limit of 2048m instead of 1792m, the memory budget of 8.5 GiB instead of 6.5 GiB, the smoke GET reading from the lake only once a run has succeeded, and the catalog spike running as its own Compose project instead of a `+uc` profile. It also accepted the two design records written during the stage, [ADR-0009](../adr/0009-read-path-query-specs-final.md) (the read path's final format, amending ADR-0005) and [ADR-0010](../adr/0010-unity-catalog-spike.md) (spike S1, positive against Unity Catalog OSS 0.6.0).

The user also decided the open questions from the report. The trivy policy is accepted, so `close-app` is gated in full and `close-spark` is gated for everything we add to it, while findings inside the Apache Spark distribution's own jars are reported on every run but not gated. Both new waivers are accepted as written (CVE-2026-25087 for pyarrow, and the AWS SDK bundle jar that hadoop-aws 3.4.2 requires), and they expire on 2026-12-31 with the platform engineering lead as owner. D19 (the GL book of record) stays open until the Stage 5 gate.

One margin was accepted knowingly. In the gate run the Spark Connect JVM held up to 1,901 MiB of process memory against its 2,048 MiB container limit (93 percent, with no kill), and SeaweedFS reached 632 of its 768 MiB, up from 428 MiB in Stage 1a. Production reads run on Databricks, so this only affects the local stack, and the user chose to fix it as the first task of Stage 2. That task measures the candidate fixes (`MALLOC_ARENA_MAX=2`, sizing the JVM to its two worker cores, a larger limit) with the read benchmark under the memory watcher and applies the one that works, and the Stage 2 gate re-proves it, because it re-runs the Stage 1b benchmark and end-to-end suite as regression. Stage 2 starts when the user gives the go-ahead.
